# فاز ۴ — نامزد انتشار

## چک‌لیست آزمون دستگاه واقعی

این موارد باید روی یک گوشی واقعی و یک تبلت واقعی، در حالت عمودی و افقی بررسی شوند.

- [ ] بازکردن فرم فاکتور و پرداخت با صفحه‌کلید باز
- [ ] دیده‌ماندن action اصلی ذخیره هنگام بازبودن صفحه‌کلید
- [ ] رعایت safe-area پایین صفحه و نوار ناوبری
- [ ] نمایش صفحه‌کلید عددی برای مبلغ و شماره پیگیری
- [ ] ورود و ویرایش تاریخ فارسی/تاریخ ثبت‌شده
- [ ] پیمایش فرم‌های طولانی بدون پوشیده‌شدن خطا یا action اصلی
- [ ] حفظ draft پس از رفتن به بخش دیگر و بازگشت
- [ ] بازگشت مرورگر از جزئیات به فهرست با حفظ فیلتر و موقعیت
- [ ] بازشدن مستقیم مسیرهای `#/invoices`، `#/payments` و `#/reports`
- [ ] گزارش‌های کارت‌محور در گوشی و گزارش جدولی در تبلت
- [ ] بررسی ظاهر روشن، تیره و مطابق دستگاه
- [ ] تست حالت آفلاین پس از یک بار بارگذاری موفق

آزمون فیزیکی در این فاز انجام نشده است. موارد بالا به تست مالک محصول روی دستگاه‌های واقعی نیاز دارند.

## PWA و دادهٔ محلی

Service worker به cache نام‌گذاری‌شدهٔ `tasviehyar-shell-v3` مهاجرت کرده است. نصب نسخهٔ جدید کش قبلی را فقط پس از فعال‌شدن نسخهٔ جدید پاک می‌کند. IndexedDB و backup format خارج از این مسیر باقی می‌مانند و service worker هیچ دادهٔ مالی را حذف نمی‌کند.

برای DirectAdmin، خروجی `dist` را روی همان origin قبلی منتشر کنید تا IndexedDB قبلی در دسترس بماند. سرور باید fallback مسیرهای navigation را به `index.html` بدهد، `sw.js` و `manifest.webmanifest` را بدون cache طولانی سرو کند، و HTTPS فعال باشد. پس از انتشار، یک بار با DevTools مقدار نسخهٔ service worker و پاسخ offline را بررسی کنید.

## محدودیت شناخته‌شده

برای آیکون‌های PWA یک SVG با اندازهٔ `any` استفاده می‌شود. برای سازگاری با نصب‌پذیری قدیمی Android می‌توان در انتشار بعدی نسخه‌های PNG با اندازهٔ ۱۹۲ و ۵۱۲ پیکسل اضافه کرد.
