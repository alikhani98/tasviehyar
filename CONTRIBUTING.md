# Contributing

Thanks for helping improve TasviehYar.

## Before you start

- Read the README and security policy
- Keep changes small and focused
- Preserve the local-first architecture
- Avoid introducing backend or cloud dependencies
- Do not commit real financial data, customer data, or backup files

## Development flow

1. Make the change on the requested branch.
2. Run `npm run typecheck`, `npm run lint`, `npm run test`, and `npm run build`.
3. Check that the diff stays within the requested scope.
4. Open an issue or pull request with a clear summary and testing notes.

## Code style

- Prefer explicit domain types and pure business rules
- Keep UI readable for Persian RTL users
- Use repository-relative paths in documentation
- Keep accessibility and mobile friendliness in mind

## Reporting issues

Use the issue tracker for bugs and feature requests.

Do not include real phone numbers, card numbers, IBANs, account numbers, customer records, or backup files.

## Licensing

No open-source license is currently granted. Contributions are accepted with the understanding that a licensing decision will be made before a stable release.
